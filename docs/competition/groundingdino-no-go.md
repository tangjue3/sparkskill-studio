# GroundingDINO `NO_GO` — 结论与对外陈述口径（Sprint 01）

> 出处：`artifacts/detect-gdino-crosscheck/analysis/run-summary.md`（2026-09-23 冻结提交后运行）。
> 本文件只做**外陈述口径整理**，不新增任何实验结论、不改写任何数字。

## 一句话结论

**`PARTIAL_TARGET_COVERAGE` + `NO_GO`**——就"用 GroundingDINO-tiny 挑战/增强本地 Qwen 的双模型 Skill"这一用途，
实测证据不足以支持启动；该结论不否认检测器作为"类别存在性第二意见"的窄用途。

## 为什么是 NO_GO（判定链）

1. 覆盖只有"类别" ⇒ 标 `PARTIAL_TARGET_COVERAGE`；
2. 信号在颜色/关系关键场景以 35.7% 误拦正确判断 ⇒ 满足"模型信号会大量误拦正确判断" ⇒ `NO_GO`；
3. 唯一窄正面（13/25 冲突中 3 个强信号）不足以形成生产双模型 Skill 的依据。

## 外陈述口径（演讲稿/字幕/答辩可用）

- 可以讲："我们测了一条热门开源检测器路线，用数据说明它**不能**做什么：不验颜色、关系不稳、
  会误拦 35.7% 的正确判断，于是我们按预注册门停止，不硬上。"
- 必须一起讲：这是**诊断**（对历史 Qwen v1 存档的交叉核验），不是同期双模型质量对照，
  不产生可部署 verdict；未测项（mAP、连续跟踪、OWLv2/YOLOE、共载经验等）原样列出。
- 禁止讲："检测器能提升准确率" / "双模型方案已就绪" / 任何把 NO_GO 讲成"将来会接入"的承诺。
- 若被问到"什么条件下重启"：`run-summary.md` 的末节三条件（能验颜色/关系的检测器 + 许可审查；
  受限 Skill 显式声明不判颜色/关系；预设误拦率上限并用 dev 集校准阈值）。
